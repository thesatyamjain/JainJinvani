## 2024-05-14 - Vite Environment Variable Leak
**Vulnerability:** The VITE_ADMIN_PASSWORD was being read as a plaintext environment variable. In Vite, any environment variable prefixed with VITE_ is statically replaced with its value during the build process, thereby exposing the plaintext password to the public bundle.
**Learning:** Client-side bundles should never include plaintext passwords or secrets as environment variables, even if they are only used to verify an input on the client-side. The public bundler will expose them.
**Prevention:** Always hash the password and provide the hash as the environment variable (e.g., VITE_ADMIN_PASSWORD_HASH), then check if the hash of the user input matches the provided hash.
## 2025-03-05 - DOMParser DOM Walking Bypass (mXSS)
**Vulnerability:** The `sanitizeHtml` function used `documentFragment.body.querySelectorAll('*')` to walk and sanitize elements. However, in certain environments or browsers, elements placed inside a `<template>` tag are parsed into a separate `DocumentFragment` attached to the `content` property, meaning they are completely skipped by standard `querySelectorAll('*')` tree traversal, allowing malicious scripts inside `<template>` tags to survive sanitization.
**Learning:** Standard DOM traversal methods might implicitly skip the inner contents of masking elements like `<template>` or `<noscript>`, or parse them differently (e.g., as text strings). When this happens, malicious payloads inside these tags are ignored during the sanitizer's removal pass, but can be activated later when injected via `innerHTML`.
**Prevention:** When writing custom sanitizers based on DOMParser, prevent Mutation XSS (mXSS) and parsing bypasses by explicitly querying and removing content-masking elements (`<template>`, `<noscript>`) and dangerous structural elements (`<math>`, `<svg>`, `<iframe>`, `<script>`, `<style>`, `<object>`, `<embed>`) *before* iterating over the general tree structure with `querySelectorAll('*')`.
