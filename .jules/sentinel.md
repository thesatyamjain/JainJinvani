## 2024-05-14 - Vite Environment Variable Leak
**Vulnerability:** The VITE_ADMIN_PASSWORD was being read as a plaintext environment variable. In Vite, any environment variable prefixed with VITE_ is statically replaced with its value during the build process, thereby exposing the plaintext password to the public bundle.
**Learning:** Client-side bundles should never include plaintext passwords or secrets as environment variables, even if they are only used to verify an input on the client-side. The public bundler will expose them.
**Prevention:** Always hash the password and provide the hash as the environment variable (e.g., VITE_ADMIN_PASSWORD_HASH), then check if the hash of the user input matches the provided hash.
## 2024-10-14 - Mutation XSS (mXSS) via content-masking tags
**Vulnerability:** The application's custom DOM-based HTML sanitizer (`sanitizeHtml.ts`) iterated over nodes using `querySelectorAll('*')` but failed to handle masking elements like `<template>` and `<noscript>` correctly. Because elements inside a `<template>` are parsed into a separate DocumentFragment, their contents bypassed standard tree traversal, allowing malicious scripts embedded within them to evade sanitization.
**Learning:** When building custom HTML sanitization using `DOMParser`, relying solely on `querySelectorAll('*')` to find all nested elements is insufficient. Tags like `<template>` and `<noscript>` hide their internal structures from standard DOM traversal APIs.
**Prevention:** Explicitly query and remove known content-masking elements (e.g., `document.querySelectorAll('template, noscript')`) *before* iterating over the main document nodes for tag/attribute sanitization.
