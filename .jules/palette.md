## 2024-03-24 - Interactive Framer Motion Component Accessibility
**Learning:** In the Jain Jinvani application, utilizing `<motion.div>` for highly interactive elements (like search results in `SearchOverlay.tsx` or `TiltCard` components) causes them to lack native keyboard focusability, screen reader semantics, and robust "Enter/Space" key triggers compared to semantic buttons. Applying generic `onClick` to a `div` is a prevalent anti-pattern.
**Action:** When creating or refactoring interactive lists or clickable cards wrapped in Framer Motion, always use `<motion.button>` rather than `<motion.div>`. Set `type="button"`, provide explicit `aria-label` attributes (e.g. for icon buttons), ensure structural alignment classes like `w-full text-left` to retain layout, and use the project's consistent `focus-visible` Tailwind classes (e.g. `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-amber-400 focus-visible:ring-offset-2`) for visual focus indicators.
