## 2024-05-23 - Debouncing Search Overlay Queries
**Learning:** In the `SearchOverlay` component, filtering content directly on every keystroke (`query`) blocks the main thread because the calculation of `categoryCounts` and `filteredItems` are synchronous and depend directly on the query state. This leads to input lag and UI stuttering on low-end devices.
**Action:** Debounced the search `query` value and replaced instances of `query` in heavy operations (like `categoryCounts`, `filteredItems` and complex UI logic) with `debouncedQuery`. This allows the input state to update instantly while deferring expensive operations to slightly later, making the UI feel smoother.
## 2024-05-24 - Memoizing Ranked Result Computations in React
**Learning:** In highly interactive search components (like `SearchOverlay.tsx`), multiple isolated `useMemo` blocks might redundantly execute the same expensive text-matching or scoring operations if they do not share a single derived source of truth. Even if an input is debounced, traversing the whole collection twice (once to count categories, once to filter lists) duplicates work.
**Action:** Lift the expensive sorting/scoring logic (`searchAndRankItems`) into a single parent `useMemo` hook (`allRankedResults`). Then, derive secondary views (like `categoryCounts` or category-specific lists) directly from that memoized subset rather than running the string-match algorithm again on the global `allItems` array.
